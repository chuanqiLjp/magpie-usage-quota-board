## 二、架构

社区插件 `@magpie-community/page-usage-tree` 已验证的成熟模式，直接沿用：

```
magpie 窗口侧边栏
  └─ page/index.html（沙盒启动器，CSP connect-src 'none'，不能联网）
        └─ 302 跳到本地服务
              └─ http://127.0.0.1:3499/（ui/，真正的页面）
                    └─ /api/board、/api/usage
                          └─ lib/gateway.mjs 调 127.0.0.1:3425
                          └─ lib/usage.mjs 只读 usage.jsonl
```

| 文件 | 职责 |
|---|---|
| `index.mjs` | 宿主部分（OpenCode v1 形式），`server` 钩子里起本地服务 |
| `lib/server.mjs` | HTTP 服务：只绑 127.0.0.1、随机 token、Host/Origin 校验、`/enter` 发 token、端口探测复用 |
| `lib/gateway.mjs` | 网关访问层（usage / quotas），候选地址含 `MAGPIE_ADDR` |
| `lib/quota.mjs` | 额度口径（窗口挑选、qwenwork 文字解析、供应商聚合）——纯函数 |
| `lib/usage.mjs` | 用量口径（四维汇总、流水账区间、最近请求索引）——纯函数 |
| `ui/` | 页面（双标签、四维表、两级折叠看板） |
| `test/` | 20 条口径单测 |

安全做法照抄社区插件：只绑回环、每请求 token 校验、Host/Origin 检查、路径穿越拒绝、不读 magpie 配置文件、不发外网。

## 三、踩坑记录（现象 → 根因 → 修复）

### 1. 插件在 Magpie 里红字报错「Is port 3499 in use?」

- **现象**：装好后插件行显示 `没有加载成功: Error: Failed to start server. Is port 3499 in use?`
- **根因**：我自验时用 `PORT=3499 node lib/server.mjs` 起的后台进程一直占着生产端口，Magpie 宿主再起服务就撞车。
- **修复**：① 杀掉自验进程；② 给 `startServer` 加启动前探测：`/healthz` 回应 `service=magpie-usage-quota-board` 就直接复用（不重复监听），被别的程序占用则抛出中文可读错误，而不是让整个插件加载失败。
- **教训**：**自验永远不要用生产端口**；插件服务要能容忍自己上一个实例的残留。

### 2. 自定义区间不生效（传 custom 却返回今天的数据）

- **现象**：`/api/usage` 传 `period=custom` 仍走网关、`from/to` 参数被忽略；非法参数也不报错。
- **根因**：`server.mjs` 的 period 白名单写成 `["today","7d","30d","all"]`，`"custom"` 被规约成 `"today"`，后面的 custom 分支永远进不去。
- **修复**：白名单补 `"custom"`，并加参数校验（缺 `from/to` 返回 400）。
- **教训**：白名单式的"兜底默认值"会静默吞掉新枚举值，加新分支时先查白名单。

### 3. 「最近请求」整列都是「—」

- **现象**：额度页最后一列全空。
- **根因**：额度接口 `/v1/magpie/quotas` 不含请求时间字段，我却在账号行里读 `lastAt`，自然为空。
- **修复**：实测发现 `usage.jsonl` 的 `providerAccount` 与额度接口的 `user` 是**同一个值**（两边都是厂商自己的账号标识字符串），于是按 `(provider, user)` 建「最后一次请求时间」索引，供应商行取其账号最晚时间。
- **教训**：跨数据源的关联键要先实测比对，不能靠字段名猜。

### 4. 自定义区间费用恒为 $0.00（误导）

- **现象**：自定义区间合计显示 `$0.00`，但 Token 有 41M。
- **根因**：`usage.jsonl` **没有 cost 字段**（只有 token/耗时/状态），价格是网关读的时候才算的。
- **修复**：统计时记录"带价格的行数"，一行都没有价格就把 `cost` 置为 `null`，前端显示「—」，脚注说明原因。
- **教训**：缺数据要显示"不知道"，不能用 0 冒充——0 是"花了 0 元"，不是"不知道"。

### 5. 额度页供应商名与数字错行

- **现象**：供应商名折行、数字整体右移一格、最近请求掉到第二行。
- **根因**：`.provider-head` 是 7 列网格，但我在第一个格子里写了**两个** `<span>`（箭头 + 名称），实际变成 8 个网格项，整行错位。
- **修复**：箭头与名称包进同一个 `.plead` 容器；同时补了缺失的列头行、把名称列从 709px 收到 300px。
- **教训**：CSS Grid 的项数必须与列数严格一致，多个视觉元素要包一层。

### 6. 「按模型」出现同名 4 行

- **现象**：`glm-5.3` 显示 4 行（125/39/26/16 次）。
- **根因**：网关 `/v1/magpie/usage` 的 `models` 数组是按「模型 × 账号」拆分的，不是按模型聚合的；我只合并了 provider 维度。
- **修复**：model 维度也按模型名合并；补单测固定该行为（3 行 → 1 行、合计 174 次）。
- **教训**：接口数组的粒度必须先验证再决定是否需要二次聚合；合并后要用"分项之和 == 合计"交叉校验。

### 7. 单测期望值自己算错

- **现象**：`totalOf` 命中率断言失败。
- **根因**：我把命中率期望写成 `缓存读 ÷ 输入`（100/200=50%），实际口径是 `缓存读 ÷ (输入+缓存读)`（100/300=33.3%）。
- **修复**：改测试期望值。
- **教训**：口径类断言要和文档定义逐字对齐，别凭直觉。

## 七、补充：Magpie 页面在沙盒里没有 localStorage（2026-11-26 复验发现）

- **现象**：插件页在 Magpie 窗口里打开后，只有表头和按钮（静态 HTML 在），**没有任何数据行，所有点击都无反应**。
- **根因**：Magpie 用 `sandbox="allow-scripts"` 的 iframe 承载插件页，**没有 `allow-same-origin`**，文档处于 opaque origin。按 HTML 规范，这种文档访问 `window.localStorage` 会抛 `SecurityError`。而 `ui/app.js` 的初始化第一件事就是 `localStorage.getItem("mqb-expanded")`，异常直接中断了整个 IIFE → 事件绑定与取数都没执行。
- **为什么之前的浏览器机验没发现**：机验是把页面当普通网页打开（正常 origin），localStorage 可用，所以一切正常。**只差一个 sandbox 属性**。
- **修复**：
  1. 抽出 `ui/store.js`：`get/set/remove` 全部 try/catch，不可用时退化为进程内内存，功能不受影响（只是刷新后不记忆）。
  2. 增加 `store.persistent()` 探测；不可用时页面右上角显示「折叠状态仅本次有效」，不静默降级。
  3. 增加全局 `error` / `unhandledrejection` 兜底，把脚本异常直接显示在页面顶部（**任何阶段崩溃都看得见，不再留一个死页面**）。
  4. 新增 `test/store.test.mjs`：用假 globalThis 模拟「localStorage 抛 SecurityError」与「根本没有 localStorage」两种环境，验证读写不抛异常、JSON 往返正确、正常环境仍走真实存储（4 条用例）。
- **教训**：
  - **页面能在浏览器打开 ≠ 能在 Magpie 里跑**。插件页的 sandbox 属性会改变可用 API，机验必须模拟 `sandbox="allow-scripts"`。
  - 初始化阶段碰任何浏览器 API（localStorage / indexedDB / cookie）都必须容错；一个异常就会让整页"活着但不动"。
  - 前端要留"崩溃可见"的兜底，否则用户只能描述"没反应"，无法定位。

### 沙盒环境的既有约束（已在实现中遵守）

| 受限能力 | 现状 |
|---|---|
| `localStorage` / `sessionStorage` | 抛 SecurityError → 已退化为内存 |
| `fetch` 同源 `'self'` | 沙盒里不可靠 → 页面走自己的本地服务（完整 http 地址），服务端配 CORS |
| 跨窗口访问 Magpie 窗口 | 不允许 → 只通过 `_magpie/bridge.js` 读主题/语言/选项 |
| 折叠状态持久化 | 沙盒下降级为「本次有效」，页面已明确提示 |

## 八、补充：沙盒里 fetch 自己的服务需要完整 CORS（2026-11-26）

- **现象**：localStorage 修好后页面能跑了（按钮有反应、错误条能显示），但表格报 `读取失败：Failed to fetch`。
- **根因**：沙盒 iframe 是不透明来源（Origin: null），页面请求自己的本地服务属于**跨源请求**。我只在预检（OPTIONS）响应里加了 `Access-Control-Allow-Origin`，**实际数据响应没有加** → 浏览器拿到响应但拒绝交给页面 → `Failed to fetch`。
- **证据**：服务端访问日志抓到 `OPTIONS /api/usage origin=null -> 204` 紧接 `POST /api/usage origin=null -> 200`，说明请求确实到达且被正确处理，问题在浏览器侧读不到响应。
- **修复**：`send()` 统一注入 CORS 头（所有响应，不只是预检），并补 `Access-Control-Allow-Private-Network: true`（Chromium 从不受信任来源访问回环地址时的 PNA 预检要求）。
- **附带修复**：Magpie **每次启动都会换 token**。页面若还带着旧 token 轮询会一直 401。现在 `api()` 把状态码带出来，401 时自动 `location.replace("/enter")` 领一次新 token（只重试一次，避免循环）。
- **新增诊断**：服务端为每个 `/api/*` 请求打一行访问日志
  `[magpie-usage-quota-board] POST /api/usage origin=null -> 200`
  以后"页面没数据"可以先看这行：有请求=前端问题，无请求=页面没起来，状态码=鉴权或逻辑问题。

### 沙盒环境完整清单（本轮全部实测）

| 能力 | 沙盒下的表现 | 插件里的处理 |
|---|---|---|
| `localStorage` | 抛 SecurityError | `store.js` 退化为内存，右上角提示「折叠状态仅本次有效」 |
| 页面内 `fetch` 同源相对路径 | 实际是跨源（opaque origin） | 服务端所有响应带 CORS + PNA 头 |
| `Origin` 请求头 | 固定为 `null` | 服务端放行 `null` |
| token | 每次 Magpie 启动都会变 | 401 自动回 `/enter` 换新 token |
| 跨窗口访问 Magpie | 不允许 | 只用 `_magpie/bridge.js` |

## 九、补充：自定义区间「按账号」显示别名（2026-11-26 修）

- **现象**：用量查看 → 汇总维度「按账号」→ 时间范围「自定义」时，名称列显示原始账号（形如 `Trae CN · 用户…`、`商汤小浣熊 · <长串 UUID>`）；切到「今天/7天/30天/全部」则正常显示别名。账号额度页的二级账号名一直是别名。
- **根因**：两条数据源的别名来源不同。
  - 网关 `/v1/magpie/usage` 的 `accounts[]` 自带 `name` 字段，值就是别名（未设别名时网关自己回退成原始账号），`summarizeGateway()` 直接用 `item.name`，所以正确。
  - 自定义区间读 `usage.jsonl`，流水行只有 `providerAccount`（原始账号），**文件里没有别名字段**；`summarizeRows()` 直接拼 `providerAccount`，所以显示原始名。
  - 别名唯一存在于 `/v1/magpie/quotas` 的 `alias` 字段（额度页 `accountRow()` 就是 `alias || user`）。
- **修复**（用户裁决：custom 分支建别名表 / 静默回退 / 只修自定义区间）：
  1. `lib/quota.mjs` 新增纯函数 `accountAliases(quotasBody)` → `Map<"provider|user", 别名>`；空别名不收录（调用方自然回退）。
  2. `lib/usage.mjs` 的 `summarizeRows(rows, dim, aliases)` 增加可选第 3 参；**分组键仍是原始 `(provider, providerAccount)`**，别名只改显示名，不参与合并与排序依据。
  3. `lib/server.mjs` 的 `period === "custom"` 分支先 `accountAliases(await gatewayQuotas())`，整体 try/catch；拉取失败就用空表静默回退原始名，不影响用量主数据。
- **键为什么必须带 provider**：同一个别名在不同供应商下是不同账号，只用账号名做键会串行。实测存在两家供应商下别名相同的账号。
- **实测覆盖**：`usage.jsonl` 里的 `(provider, providerAccount)` 组合绝大多数能在 quotas 命中别名；极少数无额度记录的账号回退原始名，符合预期。
- **回归**：`today/7d/30d/all` 走网关分支，输出与改前一致（行数与首行名称均未变）。

### 自验命令（改这条口径时照跑）

```bash
PORT=3501 node lib/server.mjs        # 不要用生产端口 3499
TOKEN=$(curl -s -o /dev/null -w '%{redirect_url}' http://127.0.0.1:3501/enter | sed 's/.*token=//')
# 自定义区间按账号：名称列应全是别名，无别名的账号显示原始名
curl -s -H "Authorization: Bearer $TOKEN" -H 'content-type: application/json' \
  -d '{"dim":"account","period":"custom","from":"2026-11-01T00:00","to":"2026-11-26T23:59"}' \
  http://127.0.0.1:3501/api/usage
```

> **Windows 自验注意**：`pkill` 对 Windows 进程无效，旧实例会继续占用端口；`startServer()` 探测到 `/healthz` 会**直接复用旧实例**，日志出现 `already serves this plugin — reusing it`——此时你测的还是旧代码。换新代码前必须先按 PID 结束：
> `netstat -ano | grep ':3501'` → `MSYS2_ARG_CONV_EXCL='*' taskkill /PID <pid> /F`
>
> **脱敏注意**：上面命令的输出会带真实账号与额度，贴进文档/Issue/PR 前必须按 `AGENTS.md` 3.5 脱敏（账号换 `账号A`/`账号B`，ID 只留前缀加 `…`，数值改成量级描述）。

## 十、补充：文档与示例一律不得出现真实账号（2026-11-26 立规）

- **背景**：本轮修别名 Bug 时，第一版开发记录直接把自验输出里的真实账号名、`iam::…` ID、额度数值粘了进去，被用户当场拦下。
- **根因**：把「自验证据」当成了必须原样保留的内容，忽略了本仓库是**公开仓库**。
- **规则**：已写入 `AGENTS.md` 第 3.5 节（最高优先级铁律），要点：
  1. 真实账户标识、凭据、额度数值，一律不得出现在代码/测试/文档/提交信息/Issue/截图/SVG。
  2. 引用真实输出做证据必须脱敏：账号换 `账号A`/`账号B`，ID 只留前缀加 `…`，数值改成量级描述。
  3. 提交前自查：`git diff --cached | grep -nE 'Bearer |sk-|iam::[0-9a-f]{8}|@phone\.local|MiniMax[0-9]'`。
  4. 历史里已泄露的，不能只删工作区文件（历史仍可检出），必须报人类决定改写历史或轮换凭据。
